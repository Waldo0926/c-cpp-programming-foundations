这是一个从 2021 年本科阶段 C/C++ 课程资料中重新整理出来的公开仓库，主要保留 **C/C++ 编程基础练习、程序调试实践与 CCF CSP 历年题代码**，并针对公开 GitHub 展示进行了清理和重构。

这个版本并不是把原始课程文件整包上传，而是有选择地保留有价值的代码，同时删除编译产物、IDE 缓存、无关资料、他人作业以及不适合公开传播的文档。

## 主要内容

- 原课程设计报告记录 **20 道 CCF CSP，总分 1970/2000**；
- 其中 **19 道 100/100**，`202112-2` 为 **70/100**；
- 根据原报告恢复 `202112-2` 当年的 70 分实现，并增加一个**基于区间聚合的优化版本**；
- 将代表性的 C 语言基础练习修正、重命名并整理为可正常编译的 C11 代码；
- 覆盖分支、循环、函数、数组、字符串、结构体、指针、链表和文件操作；
- 增加 CMake 构建配置和 GitHub Actions 自动构建检查。

### 为什么 `202112-2` 有两个版本？

原课程设计报告明确记录 `202112-2` 得分为 **70/100**，当时采用对 `[0, N)` 中每个整数逐一计算的方式，性能受到 `N` 大小直接影响。

整理原始压缩包时还发现，保存下来的 `202112-1.cpp` 与 `202112-2.cpp` 实际上完全相同，而且共同内容对应原报告中的 `202112-2` 算法，应当是后期误覆盖或误保存。因此 `202112-1` 也根据原报告恢复，`202112-2` 则保留历史 70 分逻辑并增加优化版：

- [`202112-2_historical_70.cpp`](ccf-csp/2021/202112-2_historical_70.cpp)：根据原报告中打印的代码恢复历史实现；
- [`202112-2_optimized.cpp`](ccf-csp/2021/202112-2_optimized.cpp)：现在重新实现的区间优化版本。

这样可以同时保留历史真实性，也能展示后来对时间复杂度问题的改进。

## 构建方式

需要：

- CMake 3.16+
- 支持 C11 的 GCC/Clang
- 支持 C++17 的 G++/Clang++

```bash
cmake -S . -B build
cmake --build build -j
```

本项目**没有第三方运行时依赖**，因此没有为了形式而添加 `requirements.txt`。详细说明见 [`BUILDING.md`](BUILDING.md)。

## 整理原则

原始资料里还包含大量 `.exe`、`.obj`、`.pdb`、Visual Studio 缓存、课程 PDF/Word 文档、其他同学的文件，以及明确标注不可复制传播的资料。这些都没有进入公开仓库。

另外，原课程中有不少“程序改错题”，其原始代码本身就是故意带错误的。GitHub 版本不把大量坏代码直接堆出来，而是用修正后的代表性实现展示对应知识点。

详细整理记录见 [`docs/REFACTORING_NOTES.md`](docs/REFACTORING_NOTES.md)。

## 对作品集的定位

这个仓库更适合展示**编程基础、早期学习轨迹和算法练习经历**，而不是作为生产级软件项目。它的价值在于：能够看到 C/C++ 基础、CCF CSP 训练，以及对旧代码重新审查、修正和优化的过程。
